Start Module 1

September 24 · Morning session

Create one shared repository from the Module 1 template and open it in RStudio.

Before you begin

Make sure every person in your group has completed the step-by-step setup and accepted the invitation to the dsep-ethz GitHub organization.

Check your membership in GitHub organization settings. If you cannot see dsep-ethz, ask Jory or Niál for help.

Open the Module 1 template on GitHub
1

Choose one repository creator

Create one repository per pair, not one per person. Decide who will create it; the other person will join as a collaborator.

For a group of three, still create one repository and include all three last names in its name.
2

Use the Module 1 template

  1. Sign in to the GitHub account that joined the course organization.
  2. Open the Module 1 template.
  3. Select Use this template, then Create a new repository.
3

Name and create the repository

  1. Set the Owner to dsep-ethz.
  2. Name it module1-lastname-lastname, replacing the example with every group member’s last name.
  3. Use lowercase letters and hyphens, for example module1-smith-garcia.
  4. Choose Private, leave Include all branches unselected, and select Create repository.
Owner not listed? Do not create the course repository under your personal account. Confirm that you accepted the organization invitation, then ask the teaching team for help.
4

Add collaborators

  1. Open Settings > Collaborators and teams in the new repository.
  2. Select Add people and invite every group member who did not create the repository.
  3. Add Jory Griffith, Niál Perry, and Millie Chapman using the GitHub usernames provided in class.
  4. Give collaborators Write access unless GitHub already grants access through the organization.

Each invited group member should accept the invitation before anyone begins editing.

5

Clone the repository in RStudio

  1. On GitHub, select Code, choose HTTPS, and copy the repository URL.
  2. In RStudio, select File > New Project > Version Control > Git.
  3. Paste the URL, choose where to store the project, and select Create Project.
  4. Confirm that module1.qmd, README.md, and the Git pane are visible.

Every group member should clone the same shared repository to their own computer.

6

Test the shared workflow

  1. Choose a driver and navigator. Only the driver edits.
  2. Add all group members’ names to README.md.
  3. Save, commit, and push the change.
  4. On the other computer, pull and confirm that the change appears.
  5. Switch roles before beginning Module 1.

Before starting Module 1

  • There is exactly one repository for your pair or group.
  • It belongs to dsep-ethz and includes every group member’s last name.
  • All group members, Jory, Niál, and Millie have access.
  • Every group member can pull and push.
  • The group names appear in README.md on GitHub.

Why pair programming?

Pair programming makes the reasoning behind the code visible. The driver practices explaining decisions while the navigator asks questions, catches mistakes, and keeps the larger goal in view. Switching roles helps everyone understand the full workflow, reduces the chance that one person becomes the only expert, and builds the shared Git habits needed to work together confidently.
